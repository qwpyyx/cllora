### Ours 配置

```bash
--upload_atomic_mode qv_block
--upload_score_mode sn_p1p2
--sn_p1_norm_mode depth_rank
--sn_gap_eta 1.0
--sn_force_full_budget False
--sn_save_diagnostics True
```

**代码修复**（`src/federated_uie_lora.py`）：qv-block 的 Gram 矩阵除以总维度乘积，解决 Qwen3 GQA 下 q_proj（5120-dim）主导 v_proj（1024-dim）导致的 SN estimation 偏差。

### 关键发现

1. **Qwen3 GQA 下 qv-block 需要维度归一化**：修复后 SN-P1/P2 从 18.27 → 37.00（+18.73 EM）
2. **生成 fix 对 FLASC/ComPEFT 同样关键**：修复 greedy decoding + GSM8K extractor 后 FLASC 从 7.96 → 36.77
3. **FLASC 在 12.5% 下略优于 Ours**（+0.48）：因为 FLASC 是标量级 TopK（细粒度），Ours 是 qv-block 级（粗粒度但结构一致）。预算越紧、异质性越高，Ours 优势越明显
4. **ComPEFT/FLASC encoding 对 Ours 无增益**：SN 调度后的编码反而降低性能，说明当前瓶颈不在压缩而在选择

## 1. Phase 2 — Ablation & 机制验证

### 2.1 Ablation 矩阵（只跑 Qwen3-14B + GSM8K + seed28）

| # | Variant | 配置变化 | 作用 |
|---|---|---|---|
| A1 | Ours w/o P2 | `sn_p1_norm_mode depth_rank --sn_gap_eta 0.0 --sn_force_full_budget False`（仅 P1 quota，不做 client assignment） | P2 必要性 |
| A2 | Ours w/o depth calibration | `sn_p1_norm_mode raw`（不做 depth rank normalization） | depth calibration 必要性 |
| A3 | Ours + ab_pair | `upload_atomic_mode ab_pair` | 验证 qv-block vs ab_pair 的粒度差异 |
| A4 | Ours + SN raw | `sn_p1_norm_mode raw`（raw Frobenius signal, no normalization） | signal normalization 必要性 |
