# 研究点2：实验设置

> 本文档整理当前计划投稿 IEEE INFOCOM 2027 的低预算 FedLoRA sparse upload 论文实验设计。  
> 当前实验主线应从“证明某个 Top-K score 更好”调整为“证明在现代 LLM / VLM 联邦适配场景中，通信受限的 LoRA 上传需要结构一致、表示一致、signal-noise-aware 和 allocation-aware 的调度机制”。

---

## 0. 实验设计的一句话主线

本文实验部分的核心目标是验证：

> **In low-budget federated LoRA fine-tuning, sparse upload should be scheduled over structurally coupled LoRA effective-update atoms, rather than independently sparsifying tensors or selecting magnitude-only LoRA updates.**

对应到实验设计上，需要回答五类问题：

1. **有效性**：在相同 uplink budget 下，Ours 是否优于已有 communication-efficient FedLoRA / FedLLM 方法？
2. **泛化性**：Ours 是否在不同模型族、不同参数规模、不同任务类型上稳定有效？
3. **通信效率**：Ours 是否能在较低上传比例下接近 dense FedAvg-LoRA？
4. **机制必要性**：为什么不能只用 tensor Top-K、A/B pair Top-K、effective-norm Top-K？
5. **扩展性**：Ours 是否能扩展到 MoE LLM 与 VLM 任务？

---

## 1. 模型设置

### 1.1 主实验模型

主实验不再强调 encoder-only vs. decoder-only，而是强调：

- modern LLM families；
- different deployment scales；
- dense decoder-only LLMs as the main target；
- optional MoE compatibility。

最终主实验模型如下。

| 层次 | 模型 | 模型族 | 类型 | 作用 |
|---|---|---|---|---|
| Small | **Gemma 4 E2B-it** | Gemma | small-scale modern LLM | 资源受限客户端 / 小模型代表 |
| Medium | **Llama-3.1-8B-Instruct** | Llama | dense decoder-only LLM | 国际审稿人熟悉的 8B 档主流模型 |
| Large | **Qwen3-14B-Instruct** | Qwen | dense decoder-only LLM | 14B 档现代大模型代表 |

说明：

- 如果实际环境中 Gemma 4 E2B-it checkpoint、license 或工具链不可用，可以退一步使用同规模的 **Qwen3-4B-Instruct** 或 **Llama-3.2-3B-Instruct**。
- Llama 建议优先使用 **Llama-3.1-8B-Instruct**，因为其国际可识别度更高；若实现环境中 Llama-3.1 不方便，也可以用 Llama-3-8B-Instruct。
- Qwen3-14B-Instruct 是主力 large dense LLM，用于替代已有 Qwen2.5-14B-Instruct 设置，使实验更符合 2026 年模型选择趋势。

### 1.2 MoE 补充模型

| 层次 | 模型 | 类型 | 作用 |
|---|---|---|---|
| MoE case | **Qwen3-30B-A3B** | MoE LLM, 30B total / 3B activated | 验证 Ours 对 MoE-style LLM 的兼容性 |

MoE 模型不作为主实验核心，而作为 compatibility case study。原因是 MoE 会引入 expert routing、activated parameters、expert-wise LoRA placement 和 expert imbalance 等额外变量，容易使论文主线从 sparse FedLoRA upload scheduling 偏移到 MoE-specific tuning。

建议写法：

> We further include Qwen3-30B-A3B as a MoE case study to examine the compatibility of sparse FedLoRA scheduling with emerging sparse LLM architectures.

## 2. 数据集与任务设置

实验任务以 NLP / text-centric LLM adaptation 为主，补充 1--2 个 VLM 任务。整体设计参考 FlowerTune 与 FedVLMBench 的任务覆盖思路。

### 2.1 NLP 主实验任务

主实验覆盖五类 NLP / text-centric adaptation 任务：

1. general NLP；
2. math reasoning；
3. financial domain adaptation；
4. medical domain adaptation；
5. instruction generation。

| 任务类型 | 数据集 | 推荐模型 | 主要指标 | 作用 |
|---|---|---|---|---|
| **General NLP** | **Alpaca-GPT4 fine-tuning + MMLU evaluation** | Gemma 4 E2B-it / Llama-3.1-8B-Instruct / Qwen3-14B-Instruct | Accuracy | 对齐 FlowerTune 的 general NLP 设置，验证通用指令适配与知识能力 |
| **Math Reasoning** | **GSM8K** | Gemma 4 E2B-it / Llama-3.1-8B-Instruct / Qwen3-14B-Instruct | Exact Match, Gen Len | 主推理任务，指标清晰，适合展示低预算上传对 reasoning 的影响 |
| **Financial Domain** | **FinGPT sentiment train + FPB / FIQA / TFNS evaluation** | Gemma 4 E2B-it / Llama-3.1-8B-Instruct / Qwen3-14B-Instruct | Accuracy / Macro-F1 | 代表金融隐私敏感场景，输出短，评价稳定 |
| **Medical Domain** | **Medical flashcards fine-tuning + PubMedQA / MedMCQA / MedQA / CareQA evaluation** | Gemma 4 E2B-it / Llama-3.1-8B-Instruct / Qwen3-14B-Instruct | Accuracy | 代表医疗隐私敏感场景，强化 federated learning motivation |
| **Instruction Generation** | **Databricks Dolly-15K** | Gemma 4 E2B-it / Llama-3.1-8B-Instruct / Qwen3-14B-Instruct | ROUGE-1, ROUGE-L, Gen Len; 可选 LLM-as-judge | 验证 Ours 不只适用于选择题、分类和数学 EM，也适用于开放式生成 |

说明：

- GSM8K 是当前已有实验链条最完整的数据集，建议保留为主任务之一。
- Dolly 用于开放式 instruction generation，但 EM 不适合作为主指标，应使用 ROUGE / generation length / optional LLM-as-judge。
- Financial 与 Medical 任务具有较自然的 privacy-sensitive FL 叙事，适合 INFOCOM 审稿语境。
- Code-Alpaca 暂不放入主实验。原因是 coding 任务虽然现代，但执行评估、pass@1、sandbox 环境和成本更复杂；同时其 FL privacy motivation 不如 finance / medical 自然。若后续时间充裕，可作为 appendix。

### 2.2 VLM 补充任务

VLM 任务只作为补充实验，不进入所有主实验组合。选择原则是：

- 任务形式尽量接近 instruction-response；
- 避免 detection / grounding 等复杂视觉定位任务；
- 指标尽量清晰；
- 能体现 FL privacy 或 domain adaptation 场景。

| 任务类型 | 数据集 | 推荐模型 | 主要指标 | 作用 |
|---|---|---|---|---|
| **VQA** | **Fed-SLAKE** | Qwen3-VL-8B-Instruct / Gemma 4 E2B-it if applicable | Accuracy | 医疗 VQA，代表 privacy-sensitive multimodal FL 任务 |
| **Image Captioning** | **Fed-ScienceCap** | Qwen3-VL-8B-Instruct / Gemma 4 E2B-it if applicable | CIDEr, ROUGE-L | 开放式视觉生成任务，验证 Ours 对 VLM generation 的扩展性 |

说明：

- VQA 和 Caption 是最适合本文的两个 VLM 任务，因为它们仍然可以组织为 instruction-response fine-tuning。
- 不建议加入 detection / grounding。它们会引入 IoU、bounding boxes、visual localization head、视觉标注格式等额外变量，容易偏离 sparse FedLoRA upload 主线。
- VLM 实验建议只跑一到两个模型，不需要和三个 text LLM 全部交叉。

## 4. Baseline 设计

### 4.1 Baseline 分层原则

当前实验需要区分三类方法：

1. **Main comparison baselines**：已有成熟或公开的 communication-efficient FL + LoRA / FL + LLM 方法，用于主表比较；
2. **Motivation baselines**：本文自己构造的诊断方法，用于证明设计动机；
3. **Ablation variants**：本文方法的变体，用于证明各组件必要性。

非常重要的一点是：

> AB-Factor 和 AB-Effective 不应作为最终主 baseline，而应放在 motivation / ablation / mechanism analysis 中。

原因是它们更像是本文为了逐层验证 structural consistency、representation consistency 和 magnitude-only failure 而构造的诊断基线，而不是已有成熟算法。

---

## 5. Main comparison baselines

主实验建议采用以下六个方法。

| Method | 类型 | Upload / Communication Unit | 作用 |
|---|---|---|---|
| **Dense FedAvg-LoRA** | Full communication reference | all LoRA updates | 100% uplink reference / upper reference |
| **ComPEFT**           | TopK + quantization PEFT compression         |                                                              | 代表 combined sparsification + quantization 的 PEFT 压缩方法 |
| **FLM-TopK** | FedLLM Top-K sparsification | intervalized gradients / sparse update | INFOCOM 2025 FedLLM sparse tuning baseline，最直接相关 |
| **FLASC** | Sparse FedLoRA communication | sparse LoRA communication | 代表 FedLoRA + sparse communication 的公开方法 |
| **EcoLoRA** | Communication-efficient FedLoRA | round-robin LoRA segment sharing + sparsification / encoding | 代表更系统化的通信高效 FedLoRA 方法 |
| **Ours** | Signal-noise-aware sparse FedLoRA scheduling | qv-block effective-update atom | 本文方法 |

### 5.1 Dense FedAvg-LoRA

Dense FedAvg-LoRA 上传所有 LoRA updates，是无通信限制下的 reference。本文原始优化目标就是希望 sparse aggregate 尽可能保留 dense full-upload FedLoRA 的 effective update，因此 Dense FedAvg-LoRA 必须保留。

### 5.3 FLM-TopK

FLM-TopK 是最重要的外部 baseline 之一，因为它和本文同属：

- federated LLM tuning；
- communication-efficient training；
- Top-K / sparsification；
- INFOCOM 相关社区。

它应作为主表中的直接竞争方法。

### 5.4 FLASC

FLASC 代表 FedLoRA + sparse communication 的公开方法。它与本文最接近，因为两者都围绕 LoRA fine-tuning 的稀疏通信展开。

本文需要强调区别：

- FLASC 主要是 sparse communication over LoRA parameters；
- Ours 强调 LoRA effective-update atom、signal-noise marginal gain 和 client-level allocation。

### 5.5 EcoLoRA

EcoLoRA 是 communication-efficient federated LoRA fine-tuning 方法，使用 LoRA segment sharing、adaptive sparsification 和 encoding 等机制。它适合作为系统型通信优化 baseline。

比较时需要注意：

- 如果 EcoLoRA 不能严格匹配 arbitrary budget，应报告其 native communication ratio；
- 同时尽量给出 matched-budget 或 communication-performance curve。

## 6. Motivation baselines

以下方法用于 motivation，不作为最终外部 SOTA baseline。

| Method | 放置位置 | 作用 |
|---|---|---|
| **Tensor-TopK** | Motivation | 证明普通 tensor-level Top-K 会破坏 LoRA A/B 结构 |
| **A/B pair Top-K / AB-Factor** | Motivation | 证明 A/B pair structural consistency 必要，但 factor-space norm 不够 |
| **AB-Effective** | Motivation / Mechanism | 证明 effective-update norm 虽然 representation-consistent，但 magnitude-only，不具备 signal-noise 和 allocation awareness |
| **q/v block atomic Top-K** | Motivation / Diagnostic | 证明 q/v block 作为上传 atom 是可行方向 |

### 6.1 Tensor-TopK

Tensor-TopK 把 LoRA A 和 B tensors 当作独立压缩单元，直接按 tensor norm Top-K 上传。它用于证明：

> Sparse FedLoRA cannot treat LoRA tensors as independent compression units.

### 6.2 AB-Factor

AB-Factor 以 A/B pair 为上传单元，按 factor-space norm 选择：

$$
\|U_A\|_F^2 + \|U_B\|_F^2.
$$

它满足 structural consistency，但不满足 representation consistency，因为 LoRA factorization 存在非唯一性。

### 6.3 AB-Effective

AB-Effective 以 A/B pair induced effective update norm 作为 saliency：

$$
\|\Phi\|_F^2.
$$

它满足 representation consistency，但仍然是 magnitude-only selection。它没有区分 shared signal 和 heterogeneity noise，也没有建模多个 clients 重复上传同一 module 的 diminishing returns。

## 7. Ablation variants

Ablation 用于证明 Ours 的每个组件都有必要。

| Variant | 作用 |
|---|---|
| **Single A/B-pair Ours** | 证明只在单个 A/B pair 上做 P1/P2 会出现 q/v scale bias 或 q-only selection |
| **Raw qv-block Ours** | 证明 qv-block 修复 q/v coupling，但 raw Frobenius signal 仍可能 high-layer concentration |
| **qv-block + depth-rank** | 证明 depth-aware normalization 能缓解 layer-scale bias |
| **qv-block + depth-balanced** | 最终主方法，显式控制 lower/middle/upper quota |
| **Ours w/o P2** | 只做 P1 quota，不做 client-level assignment，证明 P2 的必要性 |
| **Ours w/o signal-noise** | 用 magnitude-only quota 替代 $a_m,b_m$，证明 signal-noise decomposition 的必要性 |
| **Ours w/o calibration** | 移除 depth calibration，证明 calibration 的必要性 |

建议 final method 暂定为：

> qv-block + depth-balanced calibrated P1 + plain P2-L.

## 8. 公平比较设置

### 8.1 通信预算

主实验应采用 matched uplink budget。建议至少测试以下 budget ratios：

| Budget Ratio | 作用 |
|---:|---|
| 6.25% | 极低预算，展示低预算鲁棒性 |
| 12.5% | 主设置，对齐已有 Qwen2.5-14B/GSM8K 结果 |
| 25% | 中低预算，展示性能恢复趋势 |
| 50% | 较高预算，展示接近 dense reference 的速度 |
| 100% | Dense FedAvg-LoRA reference |

如果实验资源有限，主表可以使用 12.5%，budget curve 使用 6.25% / 12.5% / 25% / 50%。

### 8.2 比较方式

不同 baseline 的通信机制不同，因此建议使用两类比较。

#### Matched-budget comparison

所有可控稀疏率的方法在相同 per-client uplink bytes 下比较：

- FLM-TopK；
- FLASC；
- Ours；
- Random / Uniform block upload；
- Tensor-TopK / AB variants。

#### Communication-performance curve

对于通信比例不容易严格匹配的方法，绘制：

$$
\text{Task performance} \quad \text{vs.} \quad \text{uplink budget ratio}.
$$

这对 EcoLoRA、FedSA-LoRA、FFA-LoRA 等方法尤其重要。

### 8.3 统一统计口径

所有方法应报告：

| 指标 | 含义 |
|---|---|
| Per-client uplink bytes / packets | 每个 client 每轮上传量 |
| Total uplink bytes | 全部 clients 全训练过程上传量 |
| Budget ratio | 相对于 Dense FedAvg-LoRA 的上传比例 |
| Trainable parameters | 可训练 LoRA 参数量 |
| Uploaded parameters | 实际上传参数量 |
| Server-side scheduling overhead | Ours 的 P1/P2 调度开销 |
| Client-side statistic overhead | Ours 的 scalar / sketch 统计上传开销 |

## 9. FL 与 LoRA 基本设置

### 9.1 FL 设置

建议主设置延续当前已有实验中的稳定配置，并在必要时做 sensitivity。

| Setting | 推荐值 |
|---|---:|
| Total clients | 50 或 100 |
| Clients per round | 10 |
| Global rounds | 5--10 |
| Local epochs | 5 或 10 |
| Dirichlet alpha | 10 as main; additional non-IID sweep with 0.1 / 1 / 10 |
| Seeds | 28, 42, 45 |

说明：

- 若主实验任务多，建议 main table 使用 3 seeds，robustness / compatibility 使用 1 seed。
- 若计算资源紧张，可以优先保证 Qwen3-14B + GSM8K / FinGPT / Dolly 的 3 seeds。

### 9.2 LoRA 设置

| Setting | 推荐值 |
|---|---|
| LoRA rank | $r=8$ main; $r=4/16$ optional sensitivity |
| Target modules | `q_proj`, `v_proj` as main |
| Upload atom | qv-block |
| Optimizer | AdamW / Adam |
| Learning rate | $1\times 10^{-4}$ as main; avoid too small LR causing under-training |
| Adapter aggregation | FedAvg-style aggregation with dense scaling reference |

说明：

- 主方法围绕 qv-block，因此主设置建议 target modules 为 `q_proj`, `v_proj`。
- 如果扩展到 FFN LoRA 或 MoE experts，需要单独说明 upload atom 与 cost definition，不建议作为主线。

## 13. 最终推荐实验声明

论文中可以这样概括实验设置：

> We evaluate our method on representative modern LLM families and deployment scales, including Gemma 4 E2B, Llama-3.1-8B, and Qwen3-14B. The main evaluation covers five text-centric federated LLM adaptation tasks, including general NLP, mathematical reasoning, financial sentiment analysis, medical question answering, and open-ended instruction generation. We compare with full FedAvg-LoRA, rank-reduced LoRA, FLM-TopK, FLASC, and EcoLoRA under matched uplink budgets. To examine extensibility beyond dense text-only LLMs, we further include a MoE case study with Qwen3-30B-A3B and two VLM case studies on VQA and image captioning.

中文总结：

> 主实验采用 3 个现代 dense LLM、5 个 text-centric federated adaptation 任务和 5 个外部 baseline，证明 Ours 在相同通信预算下的有效性；motivation 和 ablation 使用 Tensor-TopK、AB-Factor、AB-Effective 及 Ours variants 解释方法必要性；MoE 和 VLM 作为 compatibility case study，不抢占主线。
